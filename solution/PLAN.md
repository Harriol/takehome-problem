## 1. 目标与输入输出

**目标**：给定房间轮廓（多边形，可含斜墙）和 K 个矩形物品，求出一种合法摆放
（是否可行 + 每个物品的中心点与旋转角度），空间充足时优先全部贴墙。

**输入**（JSON）：
```jsonc
{
  "boundary":  [[x,y], ...],                    // 轮廓顶点（首尾相连，mm，浮点）
  "door":      [[x1,y1], [x2,y2]],              // 门两端点（在轮廓某条边上）
  "isOpenInward": true,                          // true=内开门
  "algoToPlace": { "fridge": [L, W], "shelf-1": [L, W], ... }  // 物品名->尺寸
}
```

**输出**（JSON）：
```jsonc
{
  "feasible": true,
  "placements": [ { "name": "fridge", "center": [cx, cy], "rotation": 0 } ]
}
```
- 坐标系与输入一致（mm）；`rotation` = 物品 length 轴相对 +x 的逆时针角度（度），
  取值：{0, 90} ∪ {各条墙的方向角及其 +90}（允许沿斜墙摆放，见 2.4）。
- 不可行时 `placements: []`，附 `reason` 简述原因。
- 物品类型：fridge 冰箱（有开门边规则，2.3）；shelf 货架、overShelf 离地架、
  iceMaker 制冰机 = 普通矩形；货架的边可以贴东西，无附加限制。

## 2. 规则（已确认口径）

| 规则 | 最终口径 |
|---|---|
| 2.1 轮廓内 | 物品矩形完整位于轮廓内（可贴边，不越界） |
| 2.2 互不重叠 | 任意两物品不重叠（允许贴边）；用 shapely 相交面积≈0 判定，容差 1e-3 mm |
| 2.3 冰箱开门边 | 开门边 = 与 length 轴平行的边（两个方向任选其一，哪边能留出空间就用哪边）；该边外侧需留净空带，**净空带深度 = 冰箱的宽度值（尺寸对的第 2 个数）**；净空带必须完整在房间内，且不与其他物品相交（即开门边不能贴墙、前方不能放东西） |
| 2.4 门的遮挡与净空 | 门宽 N = 门两端点距离；门所在墙段不可被物品贴住/遮挡；**无论内开还是外开**，门内侧都预留 N×N 净空区（沿墙 N × 向室内 N），区内禁放物品；内外开仅影响渲染弧线方向 |
| 2.5 贴墙与旋转 | 物品可取朝向 {0°, 90°}；遇斜墙时，物品也可旋转到与该墙平行/垂直（即墙方向角、方向角+90°），沿斜墙贴墙放置——**斜墙同样参与贴墙** |
| 2.6 贴墙判定 | 物品某条边与墙线段共线且重合长度 ≥ 1mm 即算贴墙 |
| 2.7 多解 | 两阶段：先找"每个物品都至少贴一条墙"的解；没有则放宽为一般可行解。物品按面积从大到小放置（同面积按名字排序），固定随机种子，输出确定 |

> 2.4 是比原题更保守的口径（外开门不占用室内 N×N，但门口同样不许堵），
> 已按你的确认统一为 N×N，实现为可调参数。

## 4. 算法概要

```
读入 JSON → 预处理（规范化轮廓、算门宽 N 与净空区、解析物品）
  → 生成候选摆放位 → DFS 回溯搜索 → 独立校验 → 写 result.json + 结果图
```

**候选位生成**（每个物品，含全部朝向）：
1. 贴墙候选：把物品某边贴合墙线（含斜墙）沿线滑动，锚点取墙端点、房间角点、
   门净空区边界、已放物品边缘等在墙线上的投影位置——保证不压门区、可精确贴墙；
2. 相邻候选：贴已放物品的边放置；
3. 兜底网格：仅当前两类找不到解时启用（按尺寸粒度撒点 + 微调吸附到墙/边）。
   候选按"贴墙优先"排序。

**搜索**：DFS 回溯，逐物品尝试候选位，shapely 一次性校验全部约束
（在轮廓内、不重叠、不压门净空、冰箱净空带合法）；剪枝：
剩余物品最小面积和 > 可放置面积 ⇒ 提前失败；K ≤ 12，秒级求解，设 60s 兜底。

**不可行**：先做面积下界检查快速失败；搜索无解/超时则输出
`feasible:false` + reason，并画诊断图（轮廓 + 禁区 + 面积对比）。
